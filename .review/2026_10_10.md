репозиторию, с упором на `Platform/A2v10.Metadata` и его взаимодействие с остальной платформой.

## 1. Сначала это: безопасность и целостность данных

Эксплуатируется аутентифицированным пользователем без особых условий или теряет данные.
Порядок — по цене промедления.

1. **SQL-инъекция из строки запроса** ✔ [03/Ф14]. `Reports/TurnoverReportBuilder.cs:108`:
   значение `?Group=` (`ReportGrouping.cs:68`) вставляется в литерал `N'…'` как есть. Любой, кому
   открыт оборотный отчёт, выполняет произвольный T-SQL; гейт стоит раньше и не мешает.
   Единственное место слоя, где строка запроса попадает в текст SQL, и его не видит
   `meta validate` — SQL отчёта он не строит.
2. **Сохранение записи без транзакции** ✔ [03/Ф8], [07/С1]. `Database/SqlBuilderPlain.cs:669-714`:
   merge шапки, номер, merge строк и тегов в одном пакете с `xact_abort on`, но без `begin tran`.
   Ошибка на строках оставляет новую шапку при старых строках и израсходованный номер. Проведение
   (`SqlBuilderPost.cs:53,81`) в транзакции, сохранение — нет. Решение «Autonums» в CLAUDE.md
   отказывается от внешней транзакции ради блокировки номера, но эту цену — частично записанный
   документ — не взвешивает.
3. **Path traversal в `/_static_image`** ✔ [04/1]. `Platform.Web/Controllers/ImageController.cs:118`
   заменяет `-` на `.` уже после нормализации пути, `--/--/x-png` превращается в `../../x.png`.
   Внизу ограничения нет: `Services/Providers/InternalAppCodeProviderFile.cs:16-27` делает
   `Path.Combine` + `GetFullPath` без проверки, что результат внутри корня приложения. Тот же класс:
   `FileController.LoadFile`, `FileSystemBlobStorage` [06/19].
4. **Имя процедуры собирается из запроса** ✔ [04/4]. `DataService.LoadLazyAsync` берёт `prop` из тела
   (`Services/DataService.cs:309`) и строит `[schema].[Model.{Prop}]` (`ModelJson.cs:289-295`):
   `prop=delete` вызывает процедуру удаления через «ленивую загрузку», минуя read-only и permissions.
   То же — `DeleteProcedure(propName)`, `GetBlob` с `Key` из URL.
5. **Проверки доступа покрывают входы по-разному** [04/3], [01/11]. В `DataService` роли, permissions
   и read-only проверяются вручную в каждом методе, и в половине путей пропущены: `ExportAsync` —
   ничего; блобы — ничего; `DbRemoveAsync`, `InvokeAsync` — без read-only; metadata-ветка `Invoke`
   выходит до `CheckPermissions`; metadata-ветка `Load` выходит до `SetReadOnly`. Плюс query string
   перекрывает фиксированные `parameters` из model.json [04/5], а состояние пользователя из cookie
   «fail-open» — нет cookie, нет read-only [04/6].
6. **Identity: захват аккаунта и ключа** [06/1-6].
   - API-ключ EncodedClaims — AES-CBC без MAC со статическим IV ✔ (`Identity.Core/Helpers/AesEncrypt.cs`),
     и разные ответы на ошибку padding и ошибку JSON (`ApiKeyAuthenticationHandler.cs:64-71`) —
     padding oracle; при `SkipCheckUser` ключ не отзывается.
   - Ключ возвращается клиенту в заголовке `WWW-Authenticate` ✔ (`:61`).
   - Open redirect после входа ✔: `returnUrl` проверяется только на префикс `/account`
     (`AccountController.cs:225-228`, `:927-930`).
   - Регистрация не выключается на сервере: флаг прячет только ссылку.
   - Внешний вход привязывается к существующему аккаунту по непроверенному email и обходит 2FA.
   - Шестизначные email-коды сброса пароля перебираются без lockout.
7. **XSS** [04/2], [05/2]. Текст исключения с путём из URL уходит в SVG и в JS-шаблон без
   экранирования (`BaseController.cs:122-135`, `WebActionResult.cs:104-112`). В XAML-движке
   `TagBuilder` не кодирует ничего, а заголовки полей отчёта из DataModel попадают в Vue-шаблон
   сырыми — `{{…}}` из базы выполняется как выражение.
8. **Снять с себя роль Admin можно, обойдя отказ** ✔ [02/5]. C# сравнивает id роли ординально
   (`Admin/UserAdminBuilder.cs:94-96`), SQL-merge — по коллации базы: `"admin"` или `"Admin "`
   проходит проверку и снимает роль. Ровно тот необратимый случай, ради которого отказ заведён.
9. **MCP читает то, что экран запрещает** [02/6]. MCP решает о видимости сущности по ролям
   `model.json`, экраны при `useGrants` — по `grants`. Каталог, закрытый grants, доступен через
   `domain_info`/`entity_info`/`catalog_find`. Решения «MCP» и «Grants» в CLAUDE.md разошлись после
   введения grants.

## 2. Дефекты, ломающие работу (не безопасность)

- **Второй адрес над общей таблицей переписывает опубликованную таблицу** ✔ [02/1].
  `DatabaseMetadataProvider.cs:1094-1106` пишет в `RefTable` колонок `Parent`/`Folder` текущий
  загружаемый адрес — а таблица общая и уже опубликована. Карточка `/catalog/agent` выбирает
  папку через `/catalog/customer`, под чужим `fixed`. Зависит от порядка загрузок. Против решения
  «The bake rebuilds, never fills».
- **Взаимные `storage` (a→b→a) — StackOverflow или вечная цепочка под `_loadGate`** [02/7]; ловушка
  та же в `meta validate`.
- **Неподвижная точка карт печати не сходится**, если путь бланка возвращается в пройденную
  таблицу [03/Ф15] — зависают печать и validate.
- **Бесконечный цикл в `WorkbookHelper.GetRealRows`** при опечатке в пути диапазона бланка-книги
  [05/1]: `continue` без инкремента.
- **Флаг «нужен деплой» один на процесс, деплой — в один источник** [01/18], [02/23]: вторая база не
  деплоится. Неудачный деплой не запоминается, и один битый файл гасит все экраны [02/22]. Пять
  кешей не знают поколения — значение до `ClearAll` ложится в кеш после него [02/2].
- **`a2` CLI: композиция DI противоречит `UseAppMetadata`** ✔ [01/7]. `DatabaseMetadataProvider`
  регистрируется Singleton (`Tools/A2v10.Cli/Program.cs:99`) и потом Scoped
  (`ServicesExtensions.cs:18`); Singleton `DataService` захватывает Scoped `IAppRuntimeBuilder`.
  С проверкой графа (Development) CLI падает целиком — и ровно там, где по замыслу стоит beam.
- **`LicenseManager` никогда не сообщает Expired** [04/7]; `Bind.cs:70` даёт `format: x,,mask:` —
  SyntaxError в браузере [05/4]; `IsDebugConfiguration` зашит в `true`, отладочное UI в проде [05/3].
- **A2v10.Data: `MetadataCache` — синглтон на `Dictionary` без блокировок** [07/D1], `ClassFactory`
  пишет под блокировкой чтения [07/D2].
- **Генератор CLR-логики читает `metadata.json` в устаревшем формате** [08/1] и выводит ключ реестра из
  абсолютного пути [08/2]; стенд проверяет его на собственном форке `CatalogBase` [08/3].

## 3. Системные темы — где нарушены принципы

Отдельные находки выше — следствия нескольких причин. Чинить причину дешевле, чем каждое
следствие.

### 3.1. Шов «classic | metadata» — развилка в каждом методе, а не одна точка (DIP, OCP)

Ядро узнаёт о Metadata через `IAppRuntimeBuilder`, значение `$meta` и одну keyed-строку — граф
зависимостей направлен правильно [01, общая оценка]. Но выбор исполнителя повторён в шести
методах `DataService` и ещё в двух местах [01/10], и каждая развилка сама решает, что проверить
и какие параметры передать. Отсюда сразу три класса находок: неравномерные права и read-only
(п. 1.5), параметры хоста, которые Metadata игнорирует и собирает заново из `ICurrentUser` в
десяти местах — без `CompanyId`, с другим условием `TenantId` [01/2], и печать мимо шва по
строковому ключу `":Metadata.Report"`, записанному в двух пакетах [01/3]. Входы без развилки
(экспорт, блобы) для `$meta` строят `[dbo].[$meta.Load…]` и падают ошибкой SQL.

Сам `IAppRuntimeBuilder` толстый (ISP): HTML для layout, флаг меню, CRUD-конвейер и остатки
режима `auto`, живая реализация которого есть только в `Obsolete/` [01/1, 01/4].
`HasMetadata = Auto != null || IsMeta` склеивает два смысла.

### 3.2. У сгенерированного текста нет шва для проверки — beam не доходит до генераторов

`SqlBuilder` — 2 438 строк в 10 partial-файлах, где текст, привязка параметров и исполнение
неразделимы [03/Ф18]. Поэтому `meta validate` строит экраны и печать, но не строит SQL сохранения,
индекса и отчётов — и пп. 1.1, 1.2, [03/Ф15], [03/Ф16] проходят его зелёными. Образец решения у
автора уже есть: `PrintSqlBuilder` — текст без DI, проверяемый без базы. Распространить его на
сохранение, индекс и отчёты — прямое продолжение принципа «loop first» и цели №1 из CLAUDE.md;
прошлое ревью (§5) пришло к тому же выводу, и с тех пор это не изменилось.

То же в других местах: `XamlBeamTests` проверяет, что повторная запись даёт тот же текст, а не
что текст равен построенному объекту — симметричная потеря его не роняет [07/С5]; ни один тест
в репозитории не рендерит HTML [05/15]; генератор CLR-логики не тестируется ни в одном из двух
репозиториев [08/3].

Это главный источник тихих дефектов: каждая копия правильна на момент написания и отстаёт с
первой правкой оригинала.

### 3.4. Объявленная неизменяемость не обеспечена

CLAUDE.md держит слой на «the bake rebuilds, never fills» и «declared and resolved never share a
field». В коде опубликованные записи имеют публичные сеттеры (`TableColumn.RefTable`,
`PostMetadata.TargetTable`, `BasedOnMetadata.TargetEndpoint`, `TableMetadata`), а структурное
равенство record'ов включает мутируемый `RefTable` [02/10]. Это уже дало реальный дефект (п. 2,
первый). `DeclarationMetadata` — по-прежнему один тип для «как записано» и «как испечено» [02/14].
Решение записано, механизма у него нет: компилятор его не держит.

### 3.5. Ambient authority в собственном коде платформы

Ось bounded/ambient проведена для кода автора приложения, но не для реализации самих слоёв:
- `IServiceProvider` передаётся во все построители, SQL-построители, отчёты и `AdminGate`
  [01/8, 02/21]; в опубликованном контракте — `IModelCommand.GetCommandHandler(IServiceProvider)`,
  `IBackgroundProcessHandler.Execute(Func<IServiceProvider,Task>)` [04/14, 04/17]. У такой коробки
  нет объявленных портов: отсутствие `IAppUserAdmin` в ApiHost и CLI обнаруживается кликом.
- Веб-рантайм на первом запросе обходит все метаданные, выполняет DDL и пишет
  `deploydatabase.sql` в content root мимо `IAppCodeProvider` [01/6].
- Процессные статики: `QuestPDF.Settings` из конструктора движка [05/20],
  `DefaultThreadCurrentCulture = uk-UA` [04/22], `DateTime.Now` в лицензии [04/7].

### 3.6. Нет единого правила кодирования вывода

HTML и JS в XAML-движке не кодирует `TagBuilder`, словари локализации хранят JS-экранированное, а
`EncodeJs` вызывается точечно [05/2, 05/5]; `:class` склеивается через пробел и ломает выражения
[05/6]. Литерал `N'…'` в Metadata пишется по трём правилам, путь и имя папки идут в SQL и JS без
удвоения кавычки [03/Ф4]. Генератор вставляет значения из module.json в литералы C# сырыми [08/5].
Писатель System.Xaml не отличает литерал от разметки — место ISSUES 2.21: `XamlWriteNode.cs:97`,
`:128` в пакете, а ридер ломает и литерал `{…}`, и `{}` [07/X1]. Нужен один кодировщик на каждый
целевой язык, вызываемый в месте вывода, а не договорённость о том, что данные «уже экранированы».

### 3.7. Исключения как протокол

- `NotImplementedException` как отказ по всему репозиторию (LSP): XAML-элементы, у которых
  `RenderElement` бросает [05/7]; ошибки автора view [05/8]; `BaseModelBuilder`/`InvokeCommands`
  против контракта `IModelBuilder` (`NotSupportedException`) [02/13]; реализации в контрактном
  пакете — `MailMessage.Attachments`, `NullMailService`, `DeleteBlobAsync` [04/16, 04/18];
  8 методов `AppUserStore` [06/29].
- `catch (Exception)` переупаковывает ошибки платформы в ошибки файла автора — validate показывает
  их как находку о файле [02/13].
- Сырые сообщения (в том числе SQL с именами таблиц и ограничений) уходят клиенту: `BaseController`,
  `JsonResponse.Error`, `StimulsoftController` [04/9, 06/15, 05/13, 07/С4].
- System.Xaml обещает «XamlException — единственный тип ошибки», а летят `InvalidOperation`,
  `NotImplemented`, `FormatException` — LINE-INFO.md эти пути не накроет [07/X5].

### 3.8. Конкурентность и кеши

Общий класс по всем пакетам: синглтон или общий список, который пишут из конкурентных запросов
без синхронизации или без поколения. Metadata — кеши без поколения, флаг деплоя [02/2, 02/23];
A2v10.Data — `MetadataCache`, `ClassFactory` [07/D1, D2]; Platform.Web — `RegisterEngine` мутирует
общий список из scoped-провайдера, `WebPermissionBag` кеширует словарь первого сегмента,
`WebLocalizerDictiorany` плодит `FileSystemWatcher` [04/11-13]; Identity — счётчик неудачных входов
read-modify-write, lockout обходится параллелизмом [06/9].

### 3.9. Опубликованный контракт `A2v10.Infrastructure`

По CLAUDE.md это контракт, а не общий ящик. Фактически в нём: реализации, бросающие
`NotImplementedException` [04/16]; мёртвый дубль `IDataScripter`/`ScriptInfo` в чужом namespace,
несовместимый с настоящим [04/15]; service locator в сигнатурах [04/17]; регистрационный метод в
потребительском `IViewEngineProvider` [04/11]; `IDataService` на 17 членов [04/18];
`IAppRuntimeBuilder` с мёртвым `auto` [01/1]; `IAppUserAdmin` — три из семи членов без вызовов
[01/15]; опечатки в публичных именах (`ILocalizerDictiorany`, `LoadPermisionBagAsync`,
`InvalidReqestExecption`) [04/20]; ни одного `CancellationToken`, кроме MCP [04/19]. Каждое
исправление — breaking change; разумно копить их в один мажорный выпуск, названный заранее, а не
выпускать по одному.

### 3.10. Размер и связность

God-классы, где смешаны обязанности:
- `DatabaseMetadataProvider` — 1 353 строки, 17 обязанностей; грамматика адреса (`ParsePath`)
  фактически живёт в загрузчике и вызывается из 8 файлов [02/8];
- `Meta/TableMetadata.cs` — 27 типов в одном файле, колонка знает MCP и UI [02/9];
- `SqlBuilder` — 2 438 строк [03/Ф18], `LoadIndexModelAsync` — 466 строк [03/Ф6];
- `DataService` — ~1 000 строк, 11 зависимостей плюс `IServiceProvider` [04/18];
- `BindCmd.cs` — 746 строк, `SheetGeneratorReport.Generate` — 207 строк [05/24].

## 4. Metadata и остальная платформа — сводка по швам

Направление зависимостей правильное: Metadata → Infrastructure, App.Infrastructure, Services,
ViewEngine.Xaml; ядро о Metadata знает только через `IAppRuntimeBuilder`; A2v10.Mcp о Metadata не
знает вовсе. Слабость не в графе, а в том, что по каждому шву Metadata держит свою копию правила
платформы вместо обращения к её абстракции.

| Шов | Состояние | Главное |
|---|---|---|
| **Services** (`DataService`, `ModelJson`) | развилка в каждом методе | права, read-only и параметры хоста — неравномерно; печать мимо шва [01/2, 3, 10, 11] |
| **A2v10.Data** | правильный текстовый API, platformid последователен | свой писатель TVP; грамматика recordset-ов строками; сохранение без транзакции; `CreateCommand()` даункастом к `SqlCommand` [01/12, 01/19, 07/С1-С4] |
| **ViewEngine.Xaml / System.Xaml** | XAML-beam есть | тест проверяет идемпотентность, а не верность; писатель не отличает литерал `{` от разметки [07/С5, X1] |
| **Infrastructure** | контракт шире нужного | `IAppRuntimeBuilder` толстый, с мёртвым `auto`; `IAppUserAdmin` наполовину без вызовов [01/1, 4, 15] |
| **Platform.Web / Web.Site** | работает при правильном порядке вызовов | `ILicenseManager` (REVIEW 1.16 открыт); `<script>` на ассеты, которых не поставляет ни один пакет; деплой из рантайма [01/5, 01/6] |
| **A2v10.Mcp** | чистая граница | MCP решает по ролям, экраны — по grants; свой парсер model.json [02/6, 01/16] |
| **`a2` CLI** | единственное место, где шов ломается от окружения | двойные регистрации, captive-зависимости; ~80 публичных типов Metadata ради CLI [01/7, 01/13] |
| **A2v10.Tools** (генератор) | шов не проверен ни с одной стороны | старый формат `metadata.json`, своё «папка → вид», форк `CatalogBase` [08/1-4] |
| **App.Infrastructure** | единственная причина ссылки — CLR-хуки | подключение закомментировано, «сгенерированный» файл написан руками [01/17] |

Что даст больше всего, по одному решению на шов: одна точка выбора исполнителя в `DataService`
с одним контрактом параметров и одним местом проверки прав; композиция CLI только через
`UseAppMetadata`; явное решение о деплое из рантайма.

### 8.3. Вывод

Ранний Metadata ошибается так же, как старые слои: безопасность и целостность. Поздний почти не
вносит таких дефектов, но размножает копии правил, в том числе когда оригинал под рукой и назван

где лежит каноническая реализация каждого правила. Поэтому новая копия выглядит не нарушением, а
правильным выводом из принципа.
